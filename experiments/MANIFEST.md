# Experiments

## Batch 2 (2026-10-30): first converter output — PLEASE TEST THESE

Generated by `tools/ttf2maxine.py` from macOS system fonts. Each `.NNNN` has
a `.NNNN.png` next to it showing what the file *should* look like, rendered by
our own decoder from the finished file. Compare the CRT photo against the PNG.

| file  | source font                 | style                         | why                                                   |
|-------|-----------------------------|-------------------------------|-------------------------------------------------------|
| .9100 | Helvetica Bold, 46 lines    | No edge                       | closest possible A/B against the original `.0000`      |
| .9101 | Helvetica Bold, 40 lines    | Border, 3 lines               | tests the two-layer edge encoding (compare to `.3000`) |
| .9102 | Arial Bold Italic, 30 lines | Border & shadow, 4 lines      | tests the shadow variant (compare to `.5000`)          |
| .9103 | Georgia Bold, 46 lines      | No edge                       | a serif face the unit has never seen                   |

Test procedure, one file at a time, `.9100` first:

1. Copy the file to the unit, load it, type the standard test string:
   ```
   ABCDEFGHIJKLM
   NOPQRSTUVWXYZ
   abcdefghijklm
   nopqrstuv
   wxyz
   1234567890
   !$%'&*(),-/
   ```
   plus a second screen with `@#+=[]{}|~"\^_` and `AVATAR To Ty` (kerning).
2. Photograph the screen; note the font name the unit displays in its browser.
3. **If a file fails to load, hangs, or crashes the unit, stop and report
   which one** — that is the most valuable data point.

Things to look for: overall shape/weight, letter spacing (advance widths are
0.95× the TTF's), vertical alignment of caps vs lowercase vs punctuation,
whether the border/shadow colors separate correctly, whether `{}[]@` (codes
the original fonts never defined) render, and whether kerning pairs such as
`AV`, `To`, `Ty` close up.

## Batch 1 (2026-08-19): byte-range zeroing on `.0000` — SUPERSEDED

`.9001`–`.9006` are copies of `.0000` with one byte range zeroed each. They
were made before the format was understood and are no longer needed for
analysis; keep them only as "does a damaged file crash the unit" probes.
Known in hindsight: `.9001` wipes the glyph table (should fail to load or show
nothing), `.9002`–`.9005` wipe glyph runs for ranges of characters,
`.9006` wipes the last glyphs plus the kerning table and preview thumbnail.
